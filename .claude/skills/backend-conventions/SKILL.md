# 서버 구현 규칙

스택: Python + uv, AWS의 상시 서버 1대, Supabase(DB·로그인). 설계 근거는 `docs/HANDOFF.md` 3-6, 3-7, 4장.

## 1. 디렉터리

```
backend/
├── pyproject.toml        # uv
├── src/m30/
│   ├── adapters/         # 외부 데이터: 시세, EDGAR, 지표 일정. 인터페이스 + fake + 실제 구현
│   ├── pipeline/         # collect / classify / compute / newsline / review / publish
│   ├── arena/            # 콜 생성, 판정, 포트폴리오
│   ├── llm/              # Claude 호출, 프롬프트, 재시도
│   ├── db/               # Supabase 접근
│   └── api/              # 앱이 부르는 서버 API
└── tests/
```

architect 스펙이 다르게 정하면 스펙을 따른다.

## 2. 꼭 지킬 규칙과 이유

| 규칙 | 이유 |
| --- | --- |
| 숫자는 전부 `pipeline/compute`에서 코드로 계산하고, LLM에는 계산된 값만 넘긴다 | LLM은 숫자를 틀리게 옮긴다. 검수 단계의 숫자 대조가 이 원본을 기준으로 한다 |
| 외부 데이터는 `adapters/`의 인터페이스로만 접근한다. 모든 어댑터에 fake 구현을 둔다 | 시세 벤더가 아직 미정이다(HANDOFF 4장). fake로 개발·테스트하고 벤더는 나중에 끼운다 |
| LLM 호출은 서버에서만 한다. API 키는 `.env`에서만 읽는다 | 앱에 키를 넣으면 추출당한다(HANDOFF 3-7) |
| 뉴스 원문은 프롬프트에 데이터로만 넣는다 | 원문 안의 지시문이 모델을 조종하지 못하게 한다 |
| 무료/Plus 노출은 API 응답을 만들 때 서버가 결정한다. 애플 영수증으로 판단한다 | 앱에서 판단하면 우회된다 |
| 방향 의견(콜, 토크)은 아레나 API 응답에만 넣는다. 카드·알림·위젯 응답에 넣지 않는다 | ADR-0001 |
| 판정 기준선: 시가 체결 콜은 당일 시가 → 종가, 보유 유지 콜은 전일 종가 → 종가. 콜마다 기준선을 저장한다. 보합은 무효 | ADR-0002. 오답 삭제 불가라 기준을 바꾸면 전적이 깨진다 |
| 지수 값 대신 SPY·QQQ 가격을 쓴다 | 지수 데이터는 라이선스가 따로 필요할 수 있다 |
| 카드 조회 API는 로그인 없이 받는다: 공용 데이터만, IP당 요청 횟수 제한 + 캐시. 즉시 생성·내 종목 저장·푸시 등록은 로그인 유저만, 즉시 생성 상한은 무료 3회·Plus 10회/유저/일, 서비스 전체 300회/일. 실제 AI 생성만 센다 | 로그인 전에도 카드를 보여주되(HANDOFF 3-2), 비용이 드는 AI 생성은 계정 단위로 막는다. 익명 서버 계정은 만들지 않는다 |
| 로그인 전 요청에서 그날 카드가 없는 종목은 코드 줄만 채우고 첫 번째 줄은 "Sign in to get today's summary" 상태로 돌려준다 | 로그인 전에는 AI를 부르지 않는다 |
| 전체 즉시 생성 상한을 넘으면 코드 줄만 채우고 첫 번째 줄은 "Summary arrives tomorrow morning" 상태로 돌려준다 | 비용 상한을 서버가 지킨다 |
| 둘러보기 응답은 플랜과 무관하게 무료 범위(첫·두 번째 줄)만 담고 세 번째 줄은 잠금 상태로 보낸다. 종목별 둘러보기 조회 수를 기록한다 | 잠금은 서버가 판단한다. 조회 수는 기본 종목 분기 재선정 기준이다 |
| 무료 교체는 하루 3회. "하루"는 유저 기기 타임존 자정 기준이라 요청에 타임존을 받아 센다. 빈 슬롯 추가는 세지 않는다 | HANDOFF 3-2 |
| 카드는 (활성 종목 ∪ 기본 종목) × 거래일 단위로 한 번 만들고 모든 유저가 같이 쓴다 | 비용이 유저 수와 무관해진다 |
| 내 종목은 현재 목록 말고 추가·삭제 이력도 저장한다 | 월간 성적표가 등록일 종가부터 계산한다 |
| 시각은 동부시간(America/New_York) 기준 tz-aware로 다룬다 | 파이프라인 시각(04:00, 07:45, 16:30)이 전부 동부 기준이다 |

## 3. LLM 사용

- 모델: 분류 `claude-haiku-5-5`, 첫 번째 줄·검수·아레나 판단 `claude-sonnet-5-5`(개발 중엔 haiku), 시장 한눈에 `claude-opus-5-5`, 토크 `claude-haiku-5-5`
- 모델 ID는 설정 한 곳에 모은다. 코드 곳곳에 문자열로 흩지 않는다
- 프롬프트 캐싱: 고정 지시문 → 종목·뉴스 순서, 날짜는 user 메시지
- 출력은 JSON으로 받고 파싱 실패는 1회 재시도 후 템플릿으로 대체한다
- 문장 규칙은 `card-copy-rules` 스킬을 따른다

## 4. 테스트

```bash
cd backend && uv run pytest -q              # 기본: 네트워크 없이 fake 어댑터
cd backend && uv run pytest -q -m live      # 실제 API 호출. 사용자가 요청할 때만
```

- 기본 테스트는 네트워크 없이 결정론적으로 돈다
- 다음 경계 사례를 테스트로 덮는다: 조용한 날, 축소판, 첫 등록 종목 즉시 생성, 판정 보합, 지수 콜, 다운그레이드 잠금, 보유 유지 콜의 전일 종가 판정, 로그인 전 카드 없는 종목(코드 줄만), 즉시 생성 유저·전체 상한, 교체 4번째 시도 거절, 빈 슬롯 추가는 교체 아님, 타임존 자정 리셋
