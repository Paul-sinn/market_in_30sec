# 서버 구현 규칙

스택: Python + uv, AWS의 상시 서버 1대, Supabase(DB·로그인). 설계 근거는 `docs/HANDOFF.md` 3-6, 3-7, 4장.

## 1. 디렉터리

```
backend/
├── pyproject.toml        # uv
├── src/m30/
│   ├── adapters/         # 외부 데이터: 시세, EDGAR, 지표 일정. 인터페이스 + fake + 실제 구현
│   ├── pipeline/         # collect / classify / compute / newsline / review / publish
│   ├── arena/            # 콜 생성, 판정, 포트폴리오
│   ├── llm/              # Claude 호출, 프롬프트, 재시도
│   ├── db/               # Supabase 접근
│   └── api/              # 앱이 부르는 서버 API
└── tests/
```

architect 스펙이 다르게 정하면 스펙을 따른다.

## 2. 꼭 지킬 규칙과 이유

| 규칙 | 이유 |
| --- | --- |
| 숫자는 전부 `pipeline/compute`에서 코드로 계산하고, LLM에는 계산된 값만 넘긴다 | LLM은 숫자를 틀리게 옮긴다. 검수 단계의 숫자 대조가 이 원본을 기준으로 한다 |
| 외부 데이터는 `adapters/`의 인터페이스로만 접근한다. 모든 어댑터에 fake 구현을 둔다 | 시세 벤더가 아직 미정이다(HANDOFF 4장). fake로 개발·테스트하고 벤더는 나중에 끼운다 |
| LLM 호출은 서버에서만 한다. 비밀값(Anthropic, 시세 벤더, Supabase service role, `DISCORD_WEBHOOK_URL`, `SEC_USER_AGENT`)은 환경 변수로만 읽는다. 로그에 키·키가 들어간 URL을 남기지 않는다 | 앱에 키를 넣으면 추출당한다(HANDOFF 3-7). Marketstack은 키가 URL 쿼리에 들어간다 |
| 뉴스 원문은 프롬프트에 데이터로만 넣는다 | 원문 안의 지시문이 모델을 조종하지 못하게 한다 |
| 무료/Plus 노출은 API 응답을 만들 때 서버가 결정한다. 애플 영수증으로 판단한다 | 앱에서 판단하면 우회된다 |
| 방향 의견(콜, 토크)은 아레나 API 응답에만 넣는다. 카드·알림·위젯 응답에 넣지 않는다 | ADR-0001 |
| 판정은 모든 콜에 당일 시가 → 종가, 보합은 무효. 포트폴리오 손익은 모의 체결 기록으로 따로 계산 | ADR-0002(2026-10-18 개정). 앱 안 아레나는 개발 보류 |
| 지수 값 대신 SPY·QQQ 가격을 쓴다 | 지수 데이터는 라이선스가 따로 필요할 수 있다 |
| 카드 조회 API는 로그인 없이 받는다: 공용 데이터만, IP당 요청 횟수 제한 + 캐시. 즉시 생성·내 종목 저장·푸시 등록은 로그인 유저만, 즉시 생성 상한은 무료 3회·Plus 10회/유저/일, 서비스 전체 300회/일. 실제 AI 생성만 센다 | 로그인 전에도 카드를 보여주되(HANDOFF 3-2), 비용이 드는 AI 생성은 계정 단위로 막는다. 익명 서버 계정은 만들지 않는다 |
| 로그인 전 요청에서 그날 카드가 없는 종목은 코드 줄만 채우고 첫 번째 줄은 "Sign in to get today's summary" 상태로 돌려준다 | 로그인 전에는 AI를 부르지 않는다 |
| 전체 즉시 생성 상한을 넘으면 코드 줄만 채우고 첫 번째 줄은 "Summary arrives tomorrow morning" 상태로 돌려준다 | 비용 상한을 서버가 지킨다 |
| 둘러보기 응답은 플랜과 무관하게 무료 범위(첫·두 번째 줄)만 담고 세 번째 줄은 잠금 상태로 보낸다. 종목별 둘러보기 조회 수를 기록한다 | 잠금은 서버가 판단한다. 조회 수는 기본 종목 분기 재선정 기준이다 |
| 무료 교체는 삭제 횟수로 센다, 하루 3회. 추가는 세지 않는다. "하루"는 프로필에 저장된 타임존의 자정이고, 타임존 변경은 다음 날부터 적용한다 | HANDOFF 3-2. 삭제 후 추가나 타임존 변경으로 우회하지 못하게 |
| 카드는 (활성 종목 ∪ 기본 종목) × 거래일 단위로 한 번 만들고 모든 유저가 같이 쓴다 | 비용이 유저 수와 무관해진다 |
| 내 종목은 현재 목록 말고 추가·삭제 이력도 저장한다 | 월간 성적표가 등록일 종가부터 계산한다 |
| 시각은 동부시간(America/New_York) 기준 tz-aware로 다룬다. 거래일은 거래일 달력으로 판단하고, 휴장일엔 카드·알림을 만들지 않는다 | 파이프라인 시각(04:00, 07:45, 16:30)이 전부 동부 기준이다 |
| 줄마다 데이터 상태(확인함 / 지연 / 미지원)와 확인 시각·출처 범위를 저장한다. 수집 실패를 "없음"으로 저장하지 않는다 | "확인 못 함"을 "아무 일 없음"으로 보여주면 신뢰가 깨진다(codex 리뷰 1) |
| 내용은 닫힌 쪽으로 실패한다: 판정 단계가 실패해도 통과가 아니라 템플릿 + 보류함 | 검증 안 된 LLM 문장이 나가지 않게 |
| 가용성은 열린 쪽으로 실패한다: 소스·종목·묶음 하나의 실패는 그 범위만 "지연" | 하나 때문에 아침 카드 전체가 안 나가는 일을 막는다 |
| 재시도: 타임아웃·429·5xx·529만 지수 백오프 최대 3회. 401·403은 재시도하지 않는다 | 같은 실패를 반복하면 한도와 시간만 쓴다 |
| 실행당 LLM 호출 상한 = 생성 대상 종목 수 × 4 + 분류 묶음 수 | 버그·폭주로 비용이 튀는 걸 막는다 |
| 같은 거래일 실행은 잠금으로 하나만. 실행 기록을 남기고, 카드 내용을 바꾸면 이전 내용을 수정 이력에 남긴다. 발행 중단 플래그가 켜진 카드는 API·알림에서 뺀다 | 재실행·동시 실행에도 같은 결과, 잘못된 발행은 멈출 수 있게 |
| LLM 응답의 티커는 입력에 있던 티커만 인정한다 | 환각 티커 방지 |
| 분할일 등락률은 조정가로 계산한다. 조정가가 없거나 봉 날짜가 직전 거래일이 아니면 "지연" | 가짜 급락·오래된 값 표시 방지 |
| 숫자 반올림 규칙 하나(% 소수 첫째 자리, 금액 $94B·$1.2M)를 계산과 검수가 같이 쓴다 | 숫자 대조가 표기 차이로 어긋나지 않게 |
| SEC EDGAR는 User-Agent 필수, 초당 10회 미만. 공시는 접수번호로 중복 제거, 8-K/A는 새 소식 + 보류함 "정정 공시 있음" | SEC 공정 접근 규칙. 이미 발행된 카드는 자동으로 고치지 않는다 |
| 모든 테이블 RLS를 켠다. anon·authenticated에는 정책·테이블 권한을 주지 않는다(DB 접근은 service_role만, 앱은 서버 API로만). 스키마 테스트가 "RLS 꺼진 테이블 0개", "anon·authenticated 정책 0개"를 확인한다. `security definer` 함수는 쓰지 않는다 | 테이블 하나 빠뜨리면 전체 공개된다. anon 키는 앱에서 꺼낼 수 있어서 DB를 직접 열면 서버의 요청 제한·플랜 잠금을 우회한다 |

## 3. LLM 사용

- 모델: 분류 `claude-haiku-5-5`, 첫 번째 줄·검수·아레나 판단 `claude-sonnet-5-5`(개발 중엔 haiku), 시장 한눈에 `claude-opus-5-5`, 토크 `claude-haiku-5-5`
- 모델 ID는 설정 한 곳에 모은다. 코드 곳곳에 문자열로 흩지 않는다
- 프롬프트 캐싱: 고정 지시문 → 종목·뉴스 순서, 날짜는 user 메시지
- 출력은 JSON으로 받고 파싱 실패는 1회 재시도 후 템플릿으로 대체한다
- 문장 규칙은 `card-copy-rules` 스킬을 따른다

## 4. 테스트

```bash
cd backend && uv run pytest -q              # 기본: 네트워크 없이 fake 어댑터
cd backend && uv run pytest -q -m live      # 실제 API 호출. 사용자가 요청할 때만
```

- 기본 테스트는 네트워크 없이 결정론적으로 돈다
- 테스트 입구는 세 곳: 아침 파이프라인 실행 / 스키마 / 프로세스 출력(비밀값 노출·비로컬 DB 가드 같은 보안 규칙 전용)
- DB 연결 실패는 비밀번호 없는 메시지로 다시 던진다(`from None`). 접속 문자열을 지역 변수·예외 메시지에 들고 있지 않는다. 이유: pytest traceback은 지역 변수까지 찍는다
- 다음 경계 사례를 테스트로 덮는다: 조용한 날, 축소판, 첫 등록 종목 즉시 생성, 판정 보합, 지수 콜, 다운그레이드 잠금, 보유 유지 콜의 전일 종가 판정, 로그인 전 카드 없는 종목(코드 줄만), 즉시 생성 유저·전체 상한, 교체 4번째 시도 거절, 빈 슬롯 추가는 교체 아님, 타임존 자정 리셋
